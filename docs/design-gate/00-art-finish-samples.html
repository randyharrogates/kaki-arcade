One hawker stall, four finishes

The same game scene made four ways: a wok station, a chopping board, a plate of chicken rice and one cook. A to C are vector art written in code. D is a 3D scene modelled and rendered in Blender on this machine. Every one is a real sample of what I can deliver.

A. Plain shapes

What a prototype looks like. Readable, quick to make, and too primitive for a public release. Useful only as placeholder art while game rules are being built.

B. Flat vector Baseline

Outlines, two-tone shading, drop shadows and real ingredients on the plate. Clean and readable from the sofa. This is the minimum I would ship, and every sprite in v1 can reach it inside the build loop.

C. Rich vector

The same drawings with lighting, metal and wood texture, soft shadows, a glowing burner and steam. Still light enough for a slow TV chip. The strongest 2D option: build in B, then raise key sprites to C once the game plays well.

D. Blender render

Real 3D models with true light, reflections on the wok and steel, and soft contact shadows, rendered to flat images the game then draws. This is a first pass built from simple solids in about fifteen minutes; modelled dishes, a proper cook and textures would take it well beyond this.

Limits worth knowing: these are still sprites, so characters animate by moving, bobbing and swapping a few poses, not with fluid hand-drawn animation. All four samples are my own work. Blender 5.2 is installed on this Mac and I drive it by script, so renders fit the same build and screenshot loop as the vector art.
